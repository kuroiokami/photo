# Performance suggestion review — 2026-10-20

Reviewed the supplied suggestions against current code, rather than treating their estimated impact as measured. This pass implements cache bookkeeping, actor-owned date/JSON parser reuse and redundant decision identity lookup removal. It does not change filename order, worker concurrency, local durability, sidecar coordination or copy verification.

## Measurements and implemented changes

Run `sh scripts/benchmark.sh --hot-paths` for an isolated release benchmark. It generates and removes 4,096 synthetic 8×8 JPEGs in a temporary folder, warms each cache, times 10,000 hits, reads one EXIF-bearing JPEG 1,000 times, and reads one already-seeded decision 1,000 times from a temporary SQLite database. No user folders, shared decision database or source XMP are used. No paths, names, EXIF values or hashes are emitted. The JPEG dates are synthetic; fixtures are generated by project code rather than downloaded.

The same harness was run against baseline production code at `c41d566` and updated code on the same 18-logical-CPU Mac, macOS 27.0.1. One baseline and two updated runs are recorded in [aggregate JSON](benchmarks/2026-10-20-hot-paths.json).

| Workload | Before | After, run 1 / run 2 |
| --- | ---: | ---: |
| 10,000 cache hits, 64 entries | 167.00 ms | 39.28 / 38.92 ms |
| 10,000 cache hits, 1,024 entries | 2,636.03 ms | 39.02 / 37.53 ms |
| 10,000 cache hits, 4,096 entries | 10,635.28 ms | 38.37 / 37.80 ms |
| 1,000 EXIF-bearing JPEG metadata reads | 247.84 ms | 166.89 / 165.07 ms |
| 1,000 already-seeded JPEG decision reads | 526.64 ms | 471.38 / 483.85 ms |

The cache previously scanned an array on every hit and shifted it on eviction. Dictionary entries now link the previous/next keys, giving constant-time recency updates and eviction without reference cycles. Entries remain keyed by file and requested size, with the same session invalidation, cancellation, separate lanes and decoded-image budgets. Index bookkeeping is additional memory, as before; no new RSS measurement was made.

The metadata actor owns two fixed POSIX/UTC date formatters, for offset-bearing and wall-clock timestamps. It no longer constructs/configures a formatter for every image. Decision/metadata JSON records reuse default-configured coders within their owning store actor; ordinary decision loading and Use External reuse the already-read identity rather than repeating a filesystem stat. No schema, file-identity definition or on-disk format changes.

These are service microbenchmarks with unusually small images, warm reads, uncontrolled OS caches, no native frame timing and only one baseline. The largest cache primarily exposes scaling behavior; it does not represent a typical full-size Fit cache. The modest decision-read difference combines coder/stat changes and ordinary variation; individual savings are not isolated. None of these results establishes faster first-open RAW decoding, card throughput, full-detail rendering or representative 10–40k-shoot acceptance.

Regression coverage verifies hit recency through both lookup APIs, repeated hits, eviction, byte accounting, session reset, oversized entries and cancellation. Generated JPEGs alternate positive/negative EXIF offsets, no offset, fractions, missing/invalid dates and a subsequent valid date to catch parser-state leakage. Existing decision replacement/conflict, XMP preservation, restart, protected review and original-byte tests pass.

## Disposition of every suggestion

| Suggestion | Finding and disposition |
| --- | --- |
| 1. Natural filename collation inside comparators | Present. Its dominance at 10k+ is unmeasured. `NSSortDescriptor` alone does not cache collation keys. Keep locale/digit-aware behavior and identity ties; profile repeated sorting before considering cached filename ranks. Enumeration already runs off the main actor. |
| 2. Batch decision transactions and coordination | Valid follow-up: ordinary saves durably record intent, coordinate each XMP and acknowledge separately. Metadata batches already use a transaction. Defer a dedicated batch API until benchmarks include failure/restart/Undo and pending-intent recovery. Reusing a coordinator alone does not eliminate per-file XML/hash/I/O; coordinating a whole shoot can lengthen locks. FULL durability remains. |
| 3. Whole observable dictionaries | Per-photo publications are present. They can invalidate consumers, but dictionary mutation does not prove an entire grid redraw. Profile native observation/render cost first. Chunking must keep selected decisions actionable promptly, interactive edits intact and stale folder results rejected. No ignored dictionary/version workaround introduced. |
| 4. Parallel preview/EXIF workers | Synchronous operations serialize within each actor, but thumbnail, selected preview, metadata and detail already have separate lanes. More workers could increase RAW decoder memory/initialization contention and harm selected latency. Defer until camera-specific throughput and RSS profiles justify a bounded pool. |
| 4a. CR3 container metadata shortcut | The preview reader supplies JPEG/orientation/dimensions, not all requested EXIF. Replacing the metadata read with that result would lose shooting information. Full metadata extraction and its cold decoder cost remain open; no silent fallback to demosaicing. |
| 5. Repeated formatters/JSON coders | Implemented actor-owned reuse, measured above. No shared mutable global formatter/coder. |
| 6. Repeated selection summaries | Valid candidate: summaries/readiness materialize expanded physical targets. Cache invalidation must include selection, focused fallback, grouping, collection arrivals, decisions and readiness. Defer until large-selection render profiling; do not add a cache that can show stale batch scope. |
| 7. Linear LRU operations | Confirmed scaling bottleneck; implemented and measured above. |
| 8. Rating sort on main actor | Confirmed for batch decisions, restore and load completion; explicit sort changes already use detached snapshots with revision/session guards, and single decisions use binary insertion. Defer a dedicated asynchronous transition design that preserves pre-action auto-advance order, filtering, Undo and arrival races; do not blindly detach synchronous mutation. |
| Extra: repeated identity stat | Removed duplicate lookups in ordinary decision load and Use External. Other identity checks at independent operation boundaries remain intentional. |
| Extra: ingest checksum passes | Reads are present for original provenance and independent destination verification. Current new-file copy verifies the temporary destination before atomic publication; it does not always reread both temporary and final files. Hashing while copying could remove a source pass only with source-change/provenance tests and a real-media benchmark. Keep verification intact for now. |
| Extra: repeated marquee assignment | Present. An equality guard could reduce redundant publication, but it still compares/materializes selection. Defer until native drag profiling; preserve focused selection and range-anchor behavior. |

## Next profiling priorities

Measure batch decisions/local persistence separately from XMP publication on disposable copies; then measure 10k/40k selected-group summaries, observation invalidations and synchronous rating reorder stalls. Capture native input/frame latency and memory alongside service timings. Profile real CR3 EXIF initialization and removable-media I/O before changing decoder concurrency. These remain accepted performance investigations, not invalid suggestions or completed optimizations.
