# 0006: Verified ingest, journalled organization and metadata handoff

- Status: accepted
- Date: 2026-10-19

The user approved the ingestion/culling/keyword/IPTC/bulk-naming workflow ending in Lightroom and requested Canon and Olympus RAW support. Preserve the fast folder-first path; keep heavy detail rendering explicit and add no external package.

Use a shared MediaOperations actor for streaming SHA-256 verified copies, dual-destination manifests and two-phase rename/recovery journals. Guard asynchronous operations against actor reentrancy so a second file mutation cannot overlap ingest/handoff. Never overwrite a differing destination. Retain initial backup copies independently from later edits. Copy companions before publishing images so early culling cannot race initial XMP publication. Maintain original-name/hash evidence and update ingest destination mappings during rename/Undo. Reject changed members during recovery.

Keep long workflow operations on a separate normal-termination barrier from DecisionSaveQueue; otherwise background ingestion would delay every rating save. Both barriers drain on normal Quit. Retain the workflow model in the parent workspace so dismissing the sheet preserves progress/cancellation. Ingest can open the first completed image folder and continue while culling. New arrivals still require Reload. Other file/metadata operations remain modal.

Extend the existing actor-owned SQLite store additively for pending descriptive intent; share identities, baseline conflicts and atomic namespace-aware XMP merging with decisions. Preserve unowned develop settings and alternate-language text. Serialize XMP fragments without Foundation’s standalone XML declaration for older ImageIO readers, retaining existing packet instructions/tree; verify ImageIO acceptance directly in export tests. Distinguish omitted values from explicit clear, including empty keyword containers. Merge embedded description/keywords as the base for sidecar patches. Pending patches retain earlier unsynchronized owned fields. Keep independent star/flag semantics. Provide explicit reviewed per-file previews and local/external conflict resolution.

Use lightweight same-stem family indexes for unique RAW+JPEG grouping, physical batch targets and companion naming. Build indexes once per folder rather than scanning all files per family/action. PNGs remain independent. Grouping is a representation and targeting aid; RAW/JPEG retain distinct identities and sidecars. Reject ambiguous shared RAW sidecars across all supported RAW extension spellings; this extends decision 0005's bounded ARW lookup.

Prepare optional Lightroom handoff copies, preserving XMP **and ACR**. Since JPEG/PNG sidecars have limited interoperability, allow metadata embedding only into explicit derived handoff copies using ImageIO's CopyImageSource operation, with verification before publication. Keep source and derived checksums distinct and verify unchanged decoded pixels/orientation in tests. Do not touch Lightroom catalogs or claim verified application interoperability without a round trip.

Add CR2/CR3/CRW/ORF extension/type recognition. Default ImageIO RAW thumbnails keep both generate-from-image switches disabled. Measurement found Canon EOS R CR3's first ImageIO property/thumbnail access took about 5.1 seconds even with generation disabled. Add an independently implemented bounded BMFF reader for Canon's CMT1 dimensions/orientation and PRVW JPEG, decoding only that JPEG through ImageIO. Cap box count, metadata/preview reads and validate sizes, TIFF offsets, JPEG signature/type and EXIF orientation. Handle unknown layouts through the existing embedded-only fallback. No RAW codec or ExifTool runtime is bundled. Container field research: [ExifTool's primary QuickTime format implementation](https://github.com/exiftool/exiftool/blob/master/lib/Image/ExifTool/QuickTime.pm); the implementation here is not copied from its source. Test all eight orientations against ImageIO and malformed bounds with synthetic fixtures. Apple metadata indexing/full detail may still initialize the RAW decoder asynchronously.

Alternatives: modifying embedded library metadata risks original-byte preservation; automated Lightroom catalog changes create unnecessary coupling; copying only selected images without companions loses interoperability; treating the initial second copy as continuous backup overstates protection. A complete keyword dictionary, automatic ingest presets/renaming, live folder watching and clock correction remain subsequent work.

See WORKFLOW.md, PROJECT_STATUS.md and PERFORMANCE.md for usage, tested cameras, actual timings and remaining acceptance. Public CC0 RAW fixtures stay outside Git; only provenance and aggregate results are committed.
