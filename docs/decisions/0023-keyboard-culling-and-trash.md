# 0023: Keyboard culling, retained workflow navigation and recoverable removal

- Status: accepted
- Date: 2026-10-20

The owner requested a fast focus/orientation/crop/decision loop, clearer selected-only review, less visual refresh, an intelligible ingest return path and removal of selected rejects. This explicitly adds recoverable working-file removal to the previous read-only-original workflow; ordinary decisions and image edits continue to preserve original bytes.

Use Z for Fit/100%, B/N for unconditional photo navigation, [/] for rotation and the existing ⇧⌘C for crop. Route inspection through the existing viewport intent controller, including single-image mode and linked comparison, without speculative RAW rendering. New photos retain the existing reset-to-Fit policy. Review Only Selected requires two selected representatives in the UI, freezes physical membership and focuses one photo for individual decisions. Show All Photos clearly exits the restriction. Reserve header/decision-summary/save-line height so normal saving and entering review do not resize the preview; errors may still reveal explicit recovery controls.

Replace the workflow sheet with an in-window content view and explicit return callbacks. Retain the underlying browser identity while hidden, disable its interaction/accessibility and clear its grid focus, and keep the model/verified ingest/session/source-protection semantics. Setup can return to culling without recreating the browser. Detail cache/memory boundaries remain; this is no new throughput or peak-memory claim. Long inventories and focused confirmations may still use sheets.

Move to Trash is an explicit confirmed operation for ordinary working folders. Select Rejects (⇧⌘X) respects the visible view; grouped selections expand to physical files and the confirmation warns about picks. Flush pending decision/edit writes, require an identity for every target, freeze fingerprints and exclusive sidecars, and show the exact list. Build companion ownership indexes once per folder. Conservatively preserve shared XMP/ACR sidecars. Recheck the inventory and fingerprints before moving; check source protection/fingerprint inside each per-file write boundary and check arrivals again before sidecars. No protected source, original pixel rewrite, recursive deletion, other-folder/backup deletion or permanent-delete fallback is permitted.

Use macOS FileManager Trash, with the move adapter injectable for isolated tests. Stop at the first failure and report actual completed moves; the batch is not atomic. Track the worker in the normal-termination barrier. Restore using Finder Put Back and Reload, not culling Undo. Retain local identity-keyed records, clear the current folder's session Undo after actual image moves, and remove only moved images from the existing collection without resetting its preview-cache session. Match canonical paths to original immutable item IDs because URL standardization can change after an aliased file disappears. Reject late indexing results for removed items. Process interruption can leave image/sidecar moves split; Finder Trash plus the remaining folder files provide recovery, not a claimed transactional delete journal.

Validation and actual native results belong in PROJECT_STATUS.md and UX_REVIEW.md. Physical-card/network-volume Trash availability, broad accessibility/platform behavior and 10k/40k performance remain separate acceptance work.
